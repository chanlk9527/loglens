# LogLens：本地 App 日志分析

双击 `LogLens.html` 用 Edge / Chrome 打开。单文件包含脚本与样式，可复制给同事使用；无需安装依赖，不上传日志、不访问外部服务。关闭页面后内存中的日志清除。

`index.html` 是开发入口。修改源文件后执行 `./build.ps1` 更新独立入口。若浏览器限制 file:// 下的 Worker，可在本目录运行 `python -m http.server 8080 --bind 127.0.0.1` 后访问本地页面；该服务只提供静态资源，不接收日志上传。

## 推荐使用流程

导入后默认打开“统计概览”，通过横向标签切换内容；同一时间只展示一个视图。切换不会清除日志、筛选、报告备注或过程对比选择。

- **统计概览**：整次导入的四项指标、时间分布与跟随筛选的分析摘要。宽屏下图表与摘要并排。
- **异常记录**：默认展示 3 组，按相似记录数排序，不代表严重程度。宽屏两列卡片，支持查看相关过程、原文与单问题报告。
- **日志检索**：问题时间、场景、关键词、等级等筛选，以及原文列表。
- **业务分析**：业务字段表；业务过程与对比按需展开。
- **排查报告**：补充实际与预期现象，导出当前全局筛选范围的报告。

顶部始终显示已生效的全局筛选提示，可“恢复全部日志”。业务表独立筛选仅影响业务表。标签支持左右方向键、Home / End；小屏可横向滚动标签，图表和卡片自动改为单列。

单个问题的关联范围：该类全部候选，加上末次候选相同操作标识的记录；没有操作标识时，仅纳入同来源、同业务、前后 5 分钟内的同设备记录，以及可确认的配对响应。同设备关联标注“可能相关”。展示最多 50 条最近证据，导出保留全部关联记录。

## 已实现

- 多文件、文件夹、拖放和普通 ZIP 导入；后台 Worker 严格 UTF-8 分块解码，逐文件记录识别结果、事件数、时间范围和未归属行数。
- 标准 `[时间] [级别] [调用位置] 消息` 解析，多行消息及起止行号保留。
- 可读摘要、观察到的版本 / 系统字段、业务分类统计、请求未配对 / 冲突记录和 P95 日志间隔。
- 时间分布图、问题时间、场景、模块、级别、关键词、事件类型和业务设备筛选。
- 异常聚合卡片：次数、首次 / 末次、可能影响、下一步检查、证据入口；末次候选的后续成功证据单独标明。
- 业务过程与相关记录分页，明确标注关联依据，支持两组过程对比。
- 请求关联按来源范围、requestId、API 分组；重复 ID 或逆序保留冲突，不覆盖待配对记录。
- 配网、蓝牙、MQTT、吸奶器状态、RN / OTA、登录与验证码的业务字段提取。
- 可读报告含现象描述、覆盖、问题建议、业务过程和独立证据索引。默认省略原文，稳定替换文件 / 设备 / 请求标识。
- 合成示例含明确操作过程、扫描失败后同阶段成功、另一条成功过程，方便体验对比与证据追溯。

## 支持与限制

- 文本支持 `.log / .txt` 的上述日志格式；不是任意 Android / iOS 日志格式通用解码器。
- ZIP 支持 Store 和 Deflate，不支持加密 ZIP、ZIP64、分卷与嵌套压缩包。ZIP 内不支持的条目逐项说明。解压在内存中完成，不写入条目路径；检查大小与 CRC。浏览器需支持 `DecompressionStream('deflate-raw')`，否则请先本地解压。
- `.xlog / .mmap3` 尚不能直接解码，需要确认对应 SDK、版本、压缩 / 加密方式，以及适用的解码工具和密钥。拿到这些条件前，仅报告未分析范围。不要通过改扩展名当作文本导入。
- 单次文本 / ZIP 输入最多 100 MB，解压后的总文本也最多 100 MB；ZIP 最多 5,000 个条目；最多 250,000 条事件。超限逐项报告，结果可能只覆盖部分文件。文本与解析结果驻留内存，不是无限容量数据库。
- 时间按日志原样理解，内部用 UTC 数值做无时区算术。不同设备时区不自动校准；无记录时段不能确认日志丢失。
- 默认同文件关联，明确 sessionId 才允许同目录跨文件关联。关联 ID 必须由日志本身提供；产品设备名或 ID 与 SDK 公共参数中的手机 deviceId 区分。
- 阶段成功不代表整个业务成功。5 分钟内的同设备后续成功只是可能相关，缺少后续证据不代表持续失败。恢复观察跟随当前全局筛选。
- 图表和顶部指标展示整次导入；摘要、异常卡片、业务过程、请求质量跟随全局筛选；业务表有独立分类 / 结果 / 设备筛选。业务原文导出与业务表一致。
- 原文 JSON 不脱敏。Markdown 报告默认省略原文和环境值；现象描述只做常见规则脱敏，共享前仍需检查自由文本。
- 公司安全工具可能为 PowerShell、rg、浏览器提供不同文件视图。解码或识别失败不自动等于损坏、编码错误。

## 日志等级显示
事件表、业务表、问题过程、过程对比、上下文和原文详情均显示原始等级标签：E · 错误（红）、W · 警告（黄）、I · 信息（蓝）、D · 调试（灰）、OTHER · 未知（紫）。等级筛选也带中文名称。等级与异常候选判断相互独立；Info 记录含失败语义时仍保持 Info 标签。

## 未识别业务的异常记录
业务识别与技术类型分开：没有业务匹配时，按明确文本特征显示网络请求超时、一般超时、证书 / TLS、域名解析、接口 / HTTP、资源加载、权限、存储或运行时异常。均不是根因判断；不命中时保留来源模块并标注类型待识别。卡片展示末条消息摘要与入选原因，缺少业务阶段或关联标识时不判断恢复。首页组数是异常记录组数，不代表故障数量。
聚合保留完整多行消息的差异，仅归一化明确的标识、时间与耗时；保留 HTTP 状态码和其他长错误码。规则集中在 issue-model.js。报告保留技术类型和入选依据，仍省略原始消息。

## 解析与数量核对

- 原始等级、业务分类、日志类型、疑似异常是不同维度。原始等级不随异常判断方式改变；`🧩` 等没有明确等级含义的标签保留为 OTHER，并在摘要中展示原始标签。
- “仅按日志等级（Error）”只选 E；“等级 + 内容”额外纳入失败语义或明确业务失败。顶部、图表、异常筛选、分组与报告统一使用 `classifyAnomaly` 的结果；顶部和图表覆盖整次导入，其余跟随全局筛选。
- 业务分类先看输出模块 / 明确调用方法，再看消息开头的标签或接口。单独出现“觅睿”不再等同于配网。各业务分类互斥，“未识别业务”也可查看、筛选结果和导出，全部分类相加等于当前范围日志总数。
- 一个有效日志头计一条记录，多行消息不重复计数，空消息仍计一条。日期或格式无效的时间头单独记入未归属行，不拼入前一条，也不导致整个文件的有效记录丢弃。
- `parser-tests.js` 覆盖上述边界及逐字节 UTF-8 / CRLF 导入，随 `verify.ps1` 一起运行。

真实日志只在本地核对：`./audit-logs.ps1 -LogDirectory '日志目录'`。脚本通过严格 UTF-8 PowerShell/.NET 读取（失败时回退 rg），核对独立日志头数量、原文行覆盖、等级和业务分区总和，以及完整分块导入结果；输出聚合数量，不输出原始消息。需要模块分布时加 `-IncludeModules`。超过现有导入上限的目录需要分批核对。此次样本核对结果见 `PARSER-AUDIT.md`。
